# يومي — لوحة متابعة المهام والمكافأة

تطبيق خاص باللغة العربية وواجهة RTL لمتابعة المهام اليومية، مراجعة الخصومات، وحساب المستحق الشهري من سجلات MongoDB الفعلية.

## المتطلبات

- Node.js 22.12 أو أحدث و npm.
- MongoDB Atlas أو MongoDB متاح عبر الشبكة.
- حساب إداري وحساب عضو يتم إنشاؤهما عبر إعداد bootstrap الموضح أدناه.

## التشغيل محلياً

1. ثبّت الاعتمادات:

   ```bash
   npm install
   ```

2. انسخ `.env.example` إلى `.env` وضع اتصال MongoDB وسراً عشوائياً فريداً بطول 32 بايت أو أكثر في `AUTH_SECRET`. حدّد بيانات حسابي المسؤول والعضو بكلمات مرور قوية لا تقل عن 12 حرفاً.

3. أضف عنوان IP إلى قائمة الوصول في MongoDB Atlas، وأنشئ قاعدة البيانات/المستخدم المناسبين.

4. إذا كانت هذه قاعدة بيانات مستخدمة من إصدار سابق، افحصها **قبل تشغيل أي seeder أو ترحيل**. أمر الترحيل دون `--apply` هو **معاينة فقط** ولا يعدل قاعدة البيانات. تتطلب أوامر الترحيل تأكيداً صريحاً بأن الوجهة غير إنتاجية:

   ```bash
   npm run migrate:adhkar -- --confirm-non-production
   ```

   راجع ملخص تعريفات الأذكار والوقائع والخصومات. بعد التحقق من أن الوجهة غير إنتاجية وأخذ نسخة احتياطية، طبّق الترحيل صراحةً ثم أكمل إعداد بقية المهام والحسابات:

   ```bash
   npm run migrate:adhkar -- --apply --confirm-non-production
   npm run seed:tasks
   npm run migrate:completion-modes -- --confirm-non-production
   npm run migrate:completion-modes -- --apply --confirm-non-production
   npm run setup:users
   ```

   يضيف الأمر تعريف الصباح، ويحوّل **وثيقة المهمة الموجودة نفسها** من `morning-evening-adhkar` إلى `evening-adhkar` دون إنشاء وثيقة مساء مكررة. لا يغيّر سجلات الوقائع أو الخصومات، لذلك تبقى مراجعها إلى معرّف الوثيقة نفسه وتظل لقطات الاسم والقيمة القديمة محفوظة. لا ينفّذ الأمر ترحيلاً للسجلات القديمة إلى الصباح أو المساء.

   لقاعدة بيانات جديدة، لا يلزم ترحيل السجلات القديمة؛ أنشئ المهام مباشرة:

   ```bash
   npm run seed:tasks
   npm run migrate:completion-modes -- --confirm-non-production
   npm run migrate:completion-modes -- --apply --confirm-non-production
   npm run setup:users
   ```

   أمر إعداد الحسابات لا يستبدل كلمة مرور أي حساب موجود. بعد نجاح الإعداد، احذف متغيرات `BOOTSTRAP_*` من البيئة أو خزّنها بأمان خارج بيئة التشغيل الاعتيادية.

   ترحيل أوضاع الإكمال يعرض معاينة افتراضياً، ويتطلب `--confirm-non-production` كما يرفض `NODE_ENV=production`. عند تطبيقه، يضبط تعريف مهمة التصفح على وضع المراجعة فقط إذا لم يكن له وضع محدد بعد؛ لا يعدل الوقائع أو الخصومات السابقة. تعريفات المهام القديمة والوقائع التاريخية التي لا تحمل الوضع تستخدم الإكمال المباشر كافتراض آمن. لا تشغّل هذا الترحيل على بيانات الإنتاج ضمن هذه الخطوة.

5. شغّل التطبيق:

   ```bash
   npm run dev
   ```

   افتح <http://localhost:3000>. سجّل الدخول باسم المستخدم وكلمة المرور اللذين ضبطتهما في `.env`.

## بيئة التشغيل

- `MONGODB_URI`: سلسلة اتصال MongoDB.
- `AUTH_SECRET`: سر توقيع جلسات JWT؛ مطلوب ولا توجد بيانات دخول افتراضية.
- `APP_TIMEZONE`: المنطقة الزمنية لليوم التجاري، والافتراضي `Africa/Cairo`.
- متغيرات `BOOTSTRAP_*`: مطلوبة لعملية إعداد الحسابات فقط.

جلسة الدخول موقعة، وتنتهي بعد سبعة أيام، وتستخدم ملف تعريف ارتباط `HttpOnly` و`SameSite=Strict` و`Secure` في الإنتاج. يتم التحقق من الدور ونشاط الحساب في الخادم. ينشئ التطبيق سجلات يومية عند فتح اليوم، لكن لا ينشئ خصومات تلقائياً.

## النشر على Vercel وMongoDB Atlas

1. أنشئ قاعدة بيانات Atlas ومستخدم قاعدة بيانات بصلاحيات محدودة، واسمح باتصال Vercel حسب توثيق Atlas. خزّن `MONGODB_URI` في إعدادات المشروع لا في المستودع.
2. أضف `AUTH_SECRET` عشوائياً قوياً و`APP_TIMEZONE=Africa/Cairo` إلى بيئة Production وPreview بحسب حاجتك.
3. لا تشغّل ترحيل الأذكار على الإنتاج دون موافقة صريحة. افحص أولاً باستخدام المعاينة على قاعدة غير إنتاجية وراجع نتائجها، ثم خذ نسخة احتياطية واتبع خطة نشر معتمدة. لا تتصل خطوات التطوير أو الفحص تلقائياً بقاعدة الإنتاج.
4. نفّذ `npm run seed:tasks` و`npm run setup:users` مرة واحدة على قاعدة البيانات المقصودة عبر إجراء إعداد آمن. لا تترك متغيرات كلمات مرور bootstrap ضمن بيئة تشغيل التطبيق.
5. اربط المستودع في Vercel. يستخدم الإعداد الافتراضي `npm run build` للبناء و`npm start` للتشغيل.
6. راقب سجلات Vercel واتصالات Atlas. يستخدم التطبيق اتصال Mongoose معاد الاستخدام على مستوى العملية، ويعتمد إعدادات التجمع الافتراضية للسائق بدلاً من فرض حدود غير مبنية على حمل مقاس.

## قواعد العمل المسجلة

- قيمة المهام التسع الأولية 284 جنيه يومياً، والراتب الأساسي الشهري 8,520 جنيه. أذكار الصباح والمساء مهمتان منفصلتان بقيمة 15 جنيه لكل منهما وخصم أقصى 30 جنيه لكل مهمة.
- مبلغ الخصم يحسب كعدد صحيح من لقطة المهمة التاريخية مضروباً في المعامل المسجل وقت إنشاء السجل.
- الخصم المقترح يبقى معلقاً حتى يراجعه مسؤول؛ المعتمد وحده يقلل صافي المستحق.
- لكل خصم سجل فريد لكل وقوع مهمة، ولكل وقوع مهمة قيد فريد للعضو والمهمة والتاريخ.
- استراحة الدورة تخص مسار الدورة المحدد لذلك التاريخ ولا تعفي بقية المهام.
- تغييرات إعداد المهمة لا تعدل اللقطات والسجلات السابقة.
- المهام الجديدة تحفظ وضع الإكمال على سجل الوقوع؛ المهام ذات وضع المراجعة لا تكتمل إلا بعد موافقة مسؤول. طلبات المراجعة لا تنشئ خصومات تلقائياً، ولا يمكن اقتراح خصم قبل البت في الطلب.
- ترحيل الأذكار يحافظ على معرّف وثيقة المساء الموجودة ويغيّر تعريفها، بينما تظل الوقائع والخصومات التاريخية ولقطاتها كما هي.
- المهام الشخصية في صفحة مستقلة، محفوظة لكل عضو في مجموعة `personaltodos`، ويكون تاريخ استحقاق المهام الجديدة مطلوباً وافتراضياً تاريخ اليوم. تبقى السجلات القديمة دون تاريخ كما هي إلى أن يعدلها العضو، ولا تدخل هذه المهام في سجلات المهام اليومية أو الخصومات أو حساب المستحق.
- تعرض صفحة المهام الشخصية ملخص الإنجاز والمهام المتأخرة والمستحقة اليوم، وتبرز الأولويات بحسب تاريخ الاستحقاق.

## النطاق الحالي

تتضمن الواجهة تسجيل الدخول والخروج، لوحة المسؤول، مراجعة المهام، دفتر الخصومات مع الاعتماد/الرفض وسجل التدقيق، صفحة العضو، تسجيل إتمام الدورة والاستراحة التالية، إعدادات المهام، وتقرير شهري قابل للطباعة. لا تشمل تصدير PDF منفصلاً عن الطباعة إلى PDF من المتصفح، ولا واجهة لتعديل/إلغاء سجل استراحة بعد إنشائه؛ تُحفظ القرارات المالية كسجلات غير قابلة للحذف من الواجهة.
